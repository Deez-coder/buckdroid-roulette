# Changelog

Every change Buckdroid Roulette makes to how the game behaves, and why it exists. The game's own scripts are not
edited unless an entry says so; changes are made from our own code (autoloads), project-setting overrides applied
by the installer, and resource conversions. Gameplay logic (rounds, items, damage, dealer AI, RNG) is never changed.

Format: each entry says **what**, **where** (our file or setting), and **why**.

## Unreleased

### Game script patches
- None. All changes so far are made from our own code and settings.

### Project setting overrides (`patches/versions.json`)
- **Our autoloads load first**: `BuckdroidPlatform`, `Steam`, `BuckdroidBoot`, `BuckdroidTouch`, `BuckdroidTransparencyFallback`, inserted before the game's own autoloads. *Why:* the game's Steam autoload needs a `Steam` object to exist when it starts.
- `application/config/use_custom_user_dir = true`, `custom_user_dir_name = "BuckdroidRoulette"`. *Why:* keeps the port's saves apart from the PC game's.
- `application/boot_splash/minimum_display_time = 0`. *Why:* the 3-second splash wait shows only a black screen (the splash image is turned off).
- `input_devices/pointing/emulate_mouse_from_touch = false`. *Why:* replaced by `BuckdroidTouch` (see below).
- Android only: `rendering/renderer/rendering_method(.mobile) = "forward_plus"`, the same renderer as the PC game. *Why:* on the tested Adreno 750, Godot 4.1's Mobile renderer drops the shadows that shape the dealer's face (frame-by-frame comparison: dealer area 50% brighter and evenly lit). Forward+ on the phone matches the PC within about 1 brightness point. Compatibility loses colour adjustments and glow. Mobile and Compatibility remain candidates for lower presets on weaker phones (Phase 5).
- Android only: all of Godot's phone-only quality cuts are set back to the PC values: `force_vertex_shading.mobile = false`, `force_lambert_over_burley.mobile = false`, positional and directional shadow size 4096 with soft filter quality 2, glow upscale mode 1, sky reflections (texture arrays, 32 GGX samples, 256 reflection size). *Why:* Godot 4.1 applies these automatically on phones; vertex shading in particular made the dealer's face look flat and changed colours, and shadows became hard-edged and lower resolution. Performance cost to be measured in Phase 5, where they become part of the Low/Medium/High presets.
- Android only: `rendering/lights_and_shadows/positional_shadow/atlas_16_bits = false`. *Why:* on the tested Adreno 750, 16-bit shadow storage lost most of the shadows from the game's lights. A same-frame experiment on the phone showed 32-bit storage brings them back, matching the PC.
- Android only: `rendering/textures/vram_compression/import_etc2_astc = true`, `display/window/handheld/orientation = 4` (sensor landscape), `debug/file_logging/enable_file_logging = true`.

### Platform (`src/platform/`)
- **Steam stub** (`steam_stub.gd`, autoload `Steam`): an offline replacement for the GodotSteam functions, signals and constants the game uses. Never logged on, no lobbies or networking. *Why:* Steam does not exist on Android; the game has no ownership check, so nothing is bypassed.
- **Local achievements** (`platform.gd`): achievements the game unlocks are stored in `user://buckdroid/achievements.cfg`. *Why:* replaces Steam achievements.
- **Offline leaderboard** (`steam_stub.gd` + `platform.gd`): the Double-or-Nothing board shows this device's best score only, stored in `user://buckdroid/scores.cfg`. *Why:* the online board needs Steam; the game's board screen works unchanged.

### Multiplayer (`src/core/boot.gd`)
- The main menu's **Multiplayer** button is greyed out, cannot be pressed or focused, and shows "COMING SOON". *Why:* the game's multiplayer is built on Steam lobbies; a local multiplayer backend is planned for later.

### Input (`src/input/touch_adapter.gd`)
- **Touch adapter**: a touch moves the pointer, then presses 3 frames (about 50 ms) later; the release always follows its press. Positions are converted from game space back to window pixels before re-sending. *Why:* the game only acts on a click when something was already under the pointer, so with Godot's emulation every tap on a 3D object missed.

- **"Press any button" screens** (`touch_adapter.gd`): the end-of-run stats screen continues on any press that reaches the game's unhandled-input stage. A tap becomes a mouse click that the screen's UI overlay consumes, so taps did nothing (playtest report). While a listed screen is waiting (`EndingManager.waitingForInput`), a tap also sends a harmless input action (`buckdroid_any_button`) that the UI ignores. It's limited to listed screens because the key-rebinding menu would capture it as a new binding.
- **Relative cursor mode** (`touch_adapter.gd`, `controls.ini: touch_mode = relative`): works like a laptop trackpad. Dragging moves an on-screen cursor and a quick tap clicks at the cursor. The cursor is drawn with the game's own cursor images (pointer, hover, invalid), loaded from the user's game files at runtime, and follows the game's own show/hide and hover state. `cursor_speed` (0.25–4) and `cursor_size` (0.5–3) adjust it. *Why:* requested in the playtest; precise pointing without a finger covering the target. Direct mode remains the default.

### Settings (`src/core/settings.gd`, autoload `BuckdroidSettings`, loaded first)
- Reads `config/graphics.ini` and `config/controls.ini` from the app's external files folder (the launcher UI kit's file format and location; `user://config` on desktop). Keys so far: `shadow_mode`, `fps_cap` (30 / 60 / 0), `fps_counter`, `touch_mode`, `cursor_speed`, `cursor_size`. `controls.ini` is re-read when it changes.

### Performance overlay (`src/render/perf_overlay.gd`, `graphics.ini: fps_counter = on`)
- Top-left panel: fps, frame time (average and worst), GPU time per frame, memory, video memory, renderer, shadow mode, fps cap. Off by default.

### Rendering (`src/render/transparency_fallback.gd`)
- **Transparency fallback** (Android only): objects whose `transparency` is animated are hidden while fully transparent and shown again when the animation brings them back. *Why:* on the Mobile renderer on Android (tested on Adreno 750) animated transparency has no effect, so the DEALER/YOU choice text and blood stayed on screen. *Side effect:* those fades are instant instead of gradual.

- **Runtime shadow atlas override** (`src/render/render_settings.gd`, autoload `BuckdroidRender`, Android only): sets the root viewport's positional shadow atlas to 32-bit after startup. *Why:* the project setting above didn't take effect on the phone, and changing the viewport at runtime did. Confirmed on the phone (log shows `16-bit=false`).
- **Shadow optimizer** (`src/render/render_settings.gd`): shadows are almost the whole GPU cost of the 3D scenes on phones (S24 Ultra, idle table: 26 ms per frame with shadows, 7 ms without; each of the 14 shadowed lights costs 1–2 ms). On Android it (a) switches shadows off for lights at zero brightness (muzzle flash, item-effect lights) and back on when they light up, with no visual change; and (b) in the default "mixed" mode uses dual-paraboloid shadows (2 passes instead of 6) for the weaker fill lights, while the strong key lights that shape the dealer's face keep cube shadows. *Measured:* dealer intro 39 → 60 fps, idle table 43 → 71 fps; the dealer's face stays very close to the PC. The "cube" mode keeps the exact original look; "paraboloid" (96 fps) visibly changes the face, so it's meant for weaker phones. The game itself never changes these light settings.
- **Shadow caching fix: blinking indicators no longer cast shadows** (`render_settings.gd`, all platforms). The game's 32 small blinking indicator lights inside the table devices swap their material many times a second (script `BlinkerBranch`). Each swap counted as a shadow caster changing, so Godot redrew the shadow of every table light that reaches them, every frame, and its built-in shadow caching never worked. Found with an engine diagnostic (`engine/patches/0001`). Their shadows can't be seen, so shadow casting is switched off for exactly those meshes. *Measured:* shadow draw calls per frame 2,451 → 1,396 (PC and phone counts match); S24 Ultra GPU at the idle table, uncapped, 12.1 → 9.6–9.8 ms (about 20% less); table view picture difference 26 of 518,400 pixels (the indicators' own blink). *Heat (15 min idle at the table, no idle pacing, same start temperature as before):* skin 33 → 39.1 °C with no throttling, against 33 → 42.1 °C with moderate throttling (status 2) before the fix; processor peak 44.8 °C against 48.9 °C.
- **Big lights redraw shadows every 3rd frame on phones (engine patch 0006, graphics.ini `shadow_refresh`, default 3 on Android)**. *Why:* heat; a per-light measurement showed the backroom light alone costs ~20% of GPU load, redrawing all six cube faces every frame for the dealer's idle motion. *Measured:* GPU load at the table -13% (interval 3), -9% (interval 2). Set `shadow_refresh = 1` for the original every-frame behaviour.
- **Flicker fix (engine patch 0005)**: the Forward+ transparent pass and the shadow passes no longer share the scene-data buffer with the opaque pass (transparent uses slot 1, shadows slots 2+). *Why:* the user saw objects that can fade (health display symbols and labels, ejected shells, the sawn-off barrel tip) flicker, always at round start when the shell tray turns; every transparent object vanished for single frames when cube and paraboloid shadow redraws mixed in a frame. *Measured:* scripted repro (`flipdemo`, 20 tray turns, screen recording counted frame by frame) 4-28 vanishes per run before, 0 in 3 runs after; look unchanged. Also new dev test-driver steps `watchall`, `watchrender`, `flipdemo`, `unshade`, `keep_touch`.
- **60 Hz display on Android (engine patch 0003, setting `display/window/buckdroid_preferred_refresh_rate = 60`)**: the engine asks Android for 60 Hz on the game's surface (`Surface.setFrameRate`, Android 11+). *Why:* the user's refresh-rate overlay showed the 120 Hz panel stayed at 120 Hz while the game drew only 60 frames per second (confirmed with `dumpsys display`: renderFrameRate 120), costing display and compositor power. *Measured:* renderFrameRate 120 → 60 while the game runs.
- **Transparency fallback: only where needed** (`transparency_fallback = auto | on | off`, default auto = on only on Android with the Mobile or Compatibility renderer). *Why:* playtest report of random flicker on fading objects (life counter display, ejected shells). The fallback could show a fading object fully opaque for one frame, because an animation may set its transparency after the fallback's check in the same frame. Forward+ (the Android default now) fades those objects correctly by itself (checked on the phone: the DEALER/YOU choice text appears only while holding the shotgun).
- **New setting `render_scale`** (graphics.ini, 0.5-1.0, default 1.0): 3D resolution relative to the game's 960x540; 2D menus and text stay sharp. Requested by the user as an option.
- **Idle pacing off by default** (`idle_fps = 30` turns it on). User decision.
- **Shadow-update budget (engine patch 0002, setting `buckdroid_paraboloid_update_interval = 3` on Android)**: the weaker fill lights (dual-paraboloid shadows) redraw a changed shadow at most every third frame, taking turns; changes are kept and drawn later, so nothing is lost; the key lights (cube shadows) update every frame. *Why:* the real-play session showed 2,000-2,700 shadow draws per frame (items, hands and dealer move inside the fill lights' range), the phone at 38.9 °C with light throttling and 50 fps on average. *Measured on the S24 Ultra with our own Android engine build, uncapped, budget on vs off:* idle table 9.3 vs 11.1 ms GPU, grabbing the shotgun 10.5 vs 12.1 ms, holding it 10.5 vs 11.8 ms (about 11-16% less). Fill-light shadows can trail moving objects by up to 2 frames.
- **Shadow atlas layout: 16 full-size slots** (`render_settings.gd`, Android). Godot's default positional shadow atlas has 8 full-size slots plus 80 small ones; the dealer room has about 10-12 large, close shadow-casting lights, so they took each other's slots every frame and redrew their shadows even when nothing changed (found with the engine diagnostic's new "light shadow redrawn" log). With 4 full-size slots per quadrant, Godot's caching holds: on a still frame 0 shadow draws (from 834), while animating 1,197 (from 1,396); what still redraws are the fill lights that reach the moving dealer. *Measured on the S24 Ultra, idle table, uncapped, same run:* GPU 11.6 → 9.6-9.9 ms. Same memory; picture identical to the eye (1.6% of pixels differ by speckle at shadow edges, from some shadows getting full resolution). *Heat (run D, 15 min idle, no idle pacing):* skin 39.0 °C, processor peak 45.5 °C, no throttling, about the same as run C (39.1 / 46.8 °C). At the 60 fps cap the remaining heat is largely not the GPU: screen on at full brightness, CPU about 0.8 core, and USB charging during the tests (battery about 38 °C).
- **Idle frame pacing** (`src/render/idle_pacing.gd`, `graphics.ini: idle_fps`, default 30 on Android): while nothing on screen changes (no input, camera still for 2 s), the frame rate drops to 30; any input or camera movement restores the normal cap in the same frame. *Why:* heat. A 20-minute playtest took the phone's skin from 32 to about 41 °C, with light thermal throttling. Measured on the phone: Godot 4.1 redraws every shadow map every frame even when nothing moves (freezing all animations saved no GPU time), so a still picture costs as much as a moving one; drawing fewer frames while it's still is the remaining lever that doesn't change the look. CPU use was moderate (about 0.8 of a core across the game's threads).
  *Measured (S24 Ultra, 15 min idle at the table, same start temperature):* without idle pacing the skin went 33 → 42.1 °C with moderate throttling (status 2) after 13 minutes; with it, 33 → 36.0 °C and no throttling. This is the best case (completely still screen); real play keeps the GPU busier. It also confirms that halving GPU work saves about 6 °C, which is the target for shadow caching.
- **Adaptive shadows: no longer the default** (`render_settings.gd`, `shadow_mode = adaptive`, optional). The playtest showed items on the table lose their shadows while the dealer is off screen, because the same fill lights cast them. Android's default is back to "mixed". Original notes: like "mixed", but the table's six fill lights drop their shadows while the dealer's head isn't on screen. *Why:* heat. A same-frame comparison on the phone showed those shadows only visibly shape the dealer's face; at the table view, switching them off makes no visible difference (mean difference 0.03), and the face flattens noticeably without them (so they can't simply be removed: "key_only" mode). The head is checked each frame by projecting it into the picture, calibrated to its drawn size; the rig's bounding box and Godot's VisibleOnScreenNotifier3D both overestimated it. It only applies with the camera near the table, because lights without shadows shine through walls. *Measured on the S24 Ultra, idle table, uncapped:* GPU 13.1 → 9.5–9.9 ms (about 27% less); the dealer intro and the table view look the same as "mixed".
- Other measured options, not used as defaults (S24 Ultra, idle table, GPU ms saved): shadow edge softness 2 → 1: 0.5; hard edges: 1.1; shadow atlas 4096 → 2048: 1.0; 3D resolution 85%: 1.1; 70%: 1.9 (visibly softer). `shadow_softness` and `shadow_resolution` exist as settings for weaker phones.
- Measurement note: with the 60 fps cap the phone lowers its GPU clock to fit the work into the frame, so GPU time per frame reads about the same whatever the load. Cost comparisons must be measured uncapped (test-driver `fpscap 0`); at 60 fps, less work shows up as a lower clock and less heat.
- **60 fps cap on Android** (`src/render/render_settings.gd`). *Why:* 120 Hz phones would otherwise render up to 120 fps in a slow-paced game, using more power and heat for no visible gain. Becomes the 30/60/unlimited setting in Phase 5.

### Resources
- **Textures converted to ETC2** (`tools/transcode_etc2.gd`, PC reference for the installer step): every desktop S3TC/BPTC/RGTC texture (874, 416 MB) is decoded and re-encoded as ETC2 with mipmaps. Normal maps use Godot's ETC2 normal layout. On Android the ETC2 data is written in place of the S3TC file, so references by file name keep working, and each `.import` remap gets a `path.etc2` entry. *Why:* phones can't use S3TC; software decoding of S3TC on the phone also produced washed-out, flat colours. With ETC2 the phone's frames match the PC's average colour within about 1%. PC conversion time: 49 s.
- Dev builds only, now superseded by ETC2 (`--dev-s3tc-fallback`): texture `.import` remaps get a `path.etc2` entry pointing at the existing S3TC data, which Godot decodes in software. *Why:* lets the game load on phones before transcoding exists. Will be replaced by real ETC2 transcoding, and is never used for users.

### Test build (`tools/make_test_apk.py`)
- Adds `--use_immersive` to the start arguments. *Why:* hides the status and navigation bars so the game uses the full screen height.
